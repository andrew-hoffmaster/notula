# Product

## Register

product

## Users

Writers, developers, and note-takers who keep a folder ("vault") of plain
Markdown files. They work locally on desktop (macOS/Windows/Linux), often for
long focused sessions, and value that their notes stay as portable `.md` files
with no account, no cloud, no lock-in. They reach for Notula the way they'd
reach for Obsidian or iA Writer — a fast, trustworthy home for their writing.

## Product Purpose

Notula is a local-first desktop Markdown editor: a file tree, a tabbed
CodeMirror editing surface, and a live sanitized preview with line-mapped
scroll sync. It exports to PDF, imports from Word, and themes deeply. Success
is the tool disappearing into the writing — instant, reliable, calm — while
never getting in the way of the files being just files.

## Brand Personality

Calm, precise, trustworthy. Three words: **quiet, crafted, local**. The purple
mark (a lowercase "n" beside an asterisk) is the one spark of identity in an
otherwise restrained surface. Voice is plain and unhurried; the interface earns
trust through exactness, not decoration.

## Anti-references

- Not a SaaS dashboard: no hero metrics, no gradient cards, no marketing chrome.
- Not "AI editor" neon/glass: no glassmorphism, no gradient text, no glow-for-glow's-sake.
- Not a toy: no emoji as UI iconography, no inconsistent button shapes, no novelty affordances for standard tasks.

## Design Principles

1. **The tool disappears.** Chrome is quiet so the writing is loud. Earned
   familiarity over surprise — controls behave the way a fluent user expects.
2. **One accent, used with intent.** The Notula purple marks selection, primary
   action, and focus — never decoration.
3. **Every control is complete.** Default, hover, focus-visible, active,
   disabled — no half-built states.
4. **Precision is the aesthetic.** Hairline borders, a real spacing rhythm, a
   tuned type scale. Bold lives in the exactness, not in loudness.
5. **Local-first honesty.** The vault is plain files; the UI never pretends
   otherwise.

## Accessibility & Inclusion

Target WCAG 2.1 AA: body text ≥4.5:1, large/UI text ≥3:1, visible focus rings on
all interactive elements. Full keyboard operation (shortcuts + focus order).
Honor `prefers-reduced-motion` (state transitions only, no choreography). Theme
system covers light/dark and custom palettes for low-vision and preference needs.
